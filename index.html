2024 Research Project · Business Process Analysis · BPMN

Faculty Business Process Mapping

Role: Business Process Analyst / BPMN Modelling Contributor

A faculty-wide business process mapping project conducted in 2024 as an academic research project requested by a lecturer. The project focused on documenting and structuring business processes across the faculty, including department management, academic and student affairs, resource management, and administrative management.

Process Hierarchy Structure:

Level 0

Presents the high-level map of the faculty’s main process groups.

Level 1

Breaks down each process group into its related SOPs or main processes.

Level 2

Shows the more detailed BPMN workflow for each SOP identified in Level 1.

Identified Stakeholders

  • Students
  • Lecturers
  • Faculty management
  • Administrative staff

Key Contributions

  • Mapping faculty-wide business processes
  • Identifying process groups and process hierarchy
  • Documenting processes using BPMN Level 0 to Level 2
  • Identifying relevant stakeholders
  • Structuring process documentation

2026 Business Process Analysis · Requirements Documentation · System Implementation PT PLN Indonesia Power UBP Semarang

SIPRAKER – Internship Attendance System

Role: Solo Developer / Business Process and System Analysis Contributor

SIPRAKER is an internship attendance system developed to support attendance recording, leave submission, and attendance recap verification for internship participants at PT PLN Indonesia Power UBP Semarang.

Through this project, I worked with the existing attendance process, identified user needs, designed the workflow using BPMN in Bizagi, and translated the process into a practical system implementation.

System Scope & Supported Features

✓ Attendance recording ✓ Leave submission ✓ Admin dashboard ✓ Attendance recap ✓ Public QR verification

Key Contributions

  • Identifying user needs

  • Planning system workflow
  • Supporting database and feature planning
  • Developing the system
  • Testing the implemented features
  • Documenting the project

Methodology

How I approach a project

A simple, structured framework I follow when understanding requirements and mapping solutions.

01

Understand the context

I start by understanding the purpose of the process, the people involved, and the problem that needs to be addressed.

02

Identify user needs

I try to understand what users need, where difficulties occur, and what information is important.

03

Document the process

I organise findings into clearer workflows, requirements, diagrams, or structured documentation.

04

Connect it to a practical solution

When needed, I help translate the findings into a system concept or implementation plan.
